# 菠萝展板sk

## 用户工作总原则（用户原文，1.1完整保留）

> 专注于当前任务，不要无必要地揣测用户意图或关联历史上下文。优先遵循当前消息中的明确要求。对于仅适用于当前任务的约束，不要默认延续到后续任务。除非用户要求，否则不要添加额外备注、背景解释或无关建议，直接给出所需结果。
>
> 先先列出执行大纲一步一步进行在我确认后再进行下一步。执行时不要一直纠结当前节点，要以推进任务为主。
>
> 在进行思路发散与问题展开时你需要做到以下几点1.先检查问题有没有错误前提、逻辑跳跃和信息缺失。2.不要迎合我,要独立判断,区分事实、预测和主观观点。3.涉及数字、人物和结论时尽量核实来源。4.不同意就直接指出并给出依据、风险和替代解释。5.还要主动提醒我忽略的变量、成本和偏差。
>
> 如果用户要求你输出prompt以及生图提示词，你需要以严谨专业的ai使用者口吻，同时给我正面提示词，负面提示词以及英文补充提示词，以文字输出放到一起
>
> 任务开始前请对用户进行不断地追问以确保你有95%的把握来完成任务

### 总原则的执行解释
- 默认先简明列出与当前任务相称的执行大纲；涉及多阶段交付时逐阶段实施，每阶段展示成果并等待确认后再进入下一阶段。除非用户在本次任务里明确授权跨阶段执行，不推定此前项目的全程授权仍有效。用户仅要求一个短结果时，不制造多余阶段。
- “95%把握”是澄清充分程度的表达，不是可计算概率：优先复用本轮已给事实，只针对可能导致结果错误的关键缺口追问；不无休止地重复提问。已经有足够信息时推进任务，对非关键不确定性注明暂定。
- 执行优先级：本轮明确指令 > 当前项目已确认且仍适用的约束 > 本Skill默认流程和模板。发现当前要求与项目事实冲突时，指出冲突与影响并请用户决策；不得悄然改变明确锁定的产品几何或事实依据。
- 约束必须标注作用域（全局、项目、页面、模块、本次任务）及来源，不把一次性禁用词、尺寸、参考图或风格当成长期默认。不得为了“个性化”额外迁移无关历史内容。
- 事实、设计假设、推测与审美判断分开记录；来源不足时不编造。讨论发散时核查前提、遗漏变量、成本、风险及替代方案，但回答仍围绕用户本次目标。
- 用户只要Prompt时，仅输出所需的参考图清单及正面/负面/英文补充三段文字，不擅自调用生图工具。用户要求生成或编辑图片时，也必须先把待执行Prompt给用户审稿，收到针对该Prompt的明确确认后才可生图。除非用户要求扩展说明，不附加无关背景。工具没有独立负面提示词参数时，将约束合并入可支持的主指令，不虚构参数。

## 核心目标
将项目组织成逻辑清楚、视觉好看、适合最终展示尺寸的竞赛展板。
保持以下职责分工：
- 第一张可编辑纯几何排版示意图：约束图片位置、模块比例、文字空间和间距。
- 视觉母版：控制视觉风格与美感，生成主题背景图、装饰图形、装饰线条、色彩关系和整体氛围。
- 模块素材：在指定图片区内表达具体内容，继承母版风格。
- 最终排版：结合示意图位置、母版视觉和实际文案形成可编辑成果。
视觉母版必须好看，不得退化为只有空框与分隔线的线框图。图像位置依据当前已确认的布局版本，母版只提供视觉风格与干净负空间。

## 强制规则
1. 保持下述八步流程，用户新要求补入对应步骤，不擅自重新排序或替换流程。
2. 模块必须适合母版空间。明确图片区和文字区，使用图片区宽高比写生图Prompt，不使用整个图文模块的比例。未知尺寸/主辅权重标记暂定。
3. 不生成小号说明文字、正文、配文、注释、细小英文、数据、百分比、来源或尺寸标注。保留对应的干净排字空间，不生成假文字或密集占位线。短标题仅在用户允许时生成。
4. 不生成文字不等于删除文字区。先整理实际文案，记录文字量、字号、行距、图注与区域；试排不够时精简或重排，不默认缩小字号。正文由可编辑工具排入。
5. 用户要求Prompt或生图Prompt时，将正面提示词、负面提示词、英文补充提示词放在一起以文字输出；多参考图任务须先列出各图文件名、用途、权威范围、优先级和禁用信息。中文与英文一致。负面词按项目选择，不固定排斥摄影、高饱和或发光等风格。
6. 不编造数据、访谈、测试和技术能力；区分证据、假设、目标和占位值。精确图表与标注用可编辑工具制作。
7. 优先增量修改，保留正确成果。暂时接受不等于完成。
8. 模块必须真正引用已确定视觉规则与参考，不能仅写“风格同上”。不一口气生完整成品代替母版和模块流程。
9. 几何布局框是工作辅助，不是成品视觉元素。母版默认不生成矩形占位框、卡片底板、边框或阴影；最终排版默认不逐模块铺矩形底色。必要框线写入视觉简报，按当前项目确认方式确定用途，且保留为独立可编辑元素；不为每条普通分隔线单独询问。
10. 新项目正式制图前先复述需求供用户确认；确定视觉风格前询问偏好。不要把旧项目授权当作新项目风格确认；只有用户对本次任务明确授权跨阶段执行，才可记录授权范围并自行推进。

## 1.1 强制控制与验收门槛
11. 先分类任务：新图、产品主视觉、结构原理、故事板/人物、局部精准编辑、多素材整合、提取导出，或精确母版与最终排版；按 [prompt-schema.md](references/prompt-schema.md) 和 [prompt-templates.md](references/prompt-templates.md) 选择必要字段和模板，拒绝用同一大段通用词替代所有任务。
12. 参考资料必须给出文件名、角色与证据权限：真实 CAD/Rhino/STL 决定可核实的结构，已确认整机图决定可见外观，母版只决定视觉风格，几何示意图决定区域位置。冲突先说明；未知结构标记待确认，不能用“严格根据模型”掩盖模型资料不足。详见 [reference-control.md](references/reference-control.md)。
13. 局部修改先列出“允许修改区域/属性”“冻结区域/属性”“无法确定的部分”，采用保留原图的最小修改方案。图像工具无法保真时优先建议分层编辑/替换；不得对整图重绘后声称其余完全不变。
14. 母版视觉图片不能当作位置坐标的权威来源；可编辑布局负责图片区、标题区、文字区与图注区的真实边界。必须使用实际文案和字号试排；无法通过时调整内容或几何，不用生图后的错误区域迁移正文。仅用于风格参考的生图母版不宣称几何验收通过。
15. 故事板需要人物/产品/事件前后连续且与用户旅程分工明确。机械动作序列、实验数据、技术示意需标注“原始证据/模型推导/概念示意/已测结果”，未经核实不得虚构动作阶段、性能、尺寸或测试结论。
16. 每类验收独立记录：视觉、内容证据、结构、几何空间、文本、局部不变项、编辑器操作、导出与有效清晰度；未知/未测试不能标通过。变更触发局部回归，不因为画面好看而掩盖结构错误。
17. 原生像素、有效 PPI、透明 Alpha、可编辑文字与矢量图形分别验收；超分或重采样后的目标像素不等于恢复真实源细节。输出严格注明实际文件与待验证项。
18. 版本更新遵守原始文件不覆盖原则：仅在用户确认后生成新版本，保留旧版与可回退文件；不声称已发布、已安装或已通过平台审核。
19. **母版优先调用 image 图像生成能力，并使用该工具支持的最高原生清晰度。** 进入⑤视觉母版生成时，若当前环境可用 image（或同类 image_gen 图像生成工具），应优先用它生成视觉母版，不以网页图片搜索替代生图，也不只输出生图提示词假称已生成。按实际工具选项选择与已确认画幅方向和宽高比相符的最高原生像素及最高质量档位；若尺寸、质量参数不可显式设置，不虚构可用选项或承诺具体4K/8K。检查生成结果真实像素和细节，必要时局部修复或用分层高清图像、矢量线条及精确排版重建；插值放大须标明为重采样，不得冒充原生高清。精确页面位置与文字区域仍以可编辑布局为准。具体方法见 visual-planning.md 与 review-output.md。

20. **逐图 Prompt 预审为强制执行关卡，独立于阶段确认。** 凡将实际调用 image/image_gen 或其他图像生成/编辑能力完成视觉母版、模块、新图、局部修改、去背景、合成、风格转换、已生成图片的返修，**必须先在聊天中以文字展示本次将执行的完整 Prompt**：①参考图清单（有参考文件时列文件名、角色、优先级与禁止借用项；无参考图明确写“无”）；②【正面提示词】；③【负面提示词】；④【英文补充提示词】；⑤本次修改/不变项与关键输出规格（可嵌在以上四项内）。然后**停止在审稿节点，等待用户针对本次 Prompt 明确同意**，才允许调用工具。用户仅确认项目目标、执行大纲、风格方向、页面布局、某阶段或整个项目的授权，**都不能替代对待执行 Prompt 的审阅确认**。不允许先生成再补 Prompt，也不得将“请确认”与图像工具调用放在同一轮执行。每次 Prompt 发生实质性改写或更换参考图、目标区域，须再次展示并确认。批量生成只有在全部待用 Prompt 都事先展示且用户明确同意该批次时才可批量执行。用户在本次明确表示“不需审 Prompt、直接执行”时，记录该次豁免范围，不能推定后续任务同样豁免。工具无独立负面词参数时，保留三段式人类审阅输出，在实际调用指令中合理整合约束，不虚构参数。该关卡适用于⑤母版、⑥模块、⑦合成及所有跳步图像任务，优先于“已获得阶段授权即可继续”的通用规则。

## 1.1.1 排版决策
以信息顺序与视觉层级、网格与构图、留白与分组、图文分工、字体与色彩、内容适配、最终输出检查七项原则共同决定排版。避免矩形堆叠只是具体约束，不取代完整体系，也不禁止必要矩形；去掉边框或换成异形不等于改善排版。详细方法与来源见 [layout-principles.md](references/layout-principles.md)。

## 1.1.2 可编辑工作台
生成展板网页时使用本版 `scripts/build_editor.py` 与 `assets/editor-shell.html`、`assets/editor.css`、`assets/editor.js`。形状工具先选类型，再按下并拖动画布预览，松开才创建；单击不创建形状。Shift 约束等宽高或线条角度，Alt 从中心绘制。移动工具负责选择和移动。旧单页布局 JSON 可导入；新项目可在一个网页中包含多页。具体模型与验收见 [editable-layout.md](references/editable-layout.md)。

## 开始工作
识别当前主任务：制作展板、只写Prompt、直接生图、最终排版，或迭代本Skill。
迭代Skill时，案例图服务于验证，不能擅自把案例成品制作变成主任务；依据结果写规则，不把未完成项标通过。
读取已有成果与用户确认，从当前阶段继续。已有需求、风格、布局不重复询问；只写Prompt、只修一模块或只排版时只执行相关阶段，不重走八步。无法访问的文件如实说明。
需求确认、布局确认、视觉方向/母版确认是默认主要节点；⑥按模块确认。只有用户对本次任务明确授权跨阶段执行，才可合并阶段确认；不能沿用旧授权。**即使获准合并阶段，也不可绕过独立的逐图Prompt预审关卡**（除非用户就本次明确豁免）。修改本Skill不是启动新的展板制作。
调用生图、PDF等工具前遵循相应技能。缺工具时说明限制，不假设能执行。

## 八步工作流
### ① 接收与盘点
整理项目要求、成品尺寸方向页数、现有资料、已有素材、缺失信息及交付形式；确认产品是否定稿。
正式制图前增加三项：先汇总用户已有要求；用简短需求对齐单复述主题、用途、尺寸页数、必备内容、资料边界、文字规则、交付格式和确认方式；请用户确认或纠正后再进入正式制作。已知要求不要重复问，缺失项明确暂定。如本次任务明确获得跨阶段授权，可先展示对齐单并记录假设，自行推进已授权阶段，不反复追问。
### ② 内容与证据整理
确定核心论点、数据来源、设计假设、模块职责；整理实际说明文案，避免信息重复。明确首眼核心信息和支撑证据，为每张计划图片指定解释任务，不按现有素材数量平均分配版面。
### ③ 页面规划
确定每页讲什么、主次、阅读顺序、信息量与空间预算。分别分配图片区、标题区、正文区、图注区与间距。按 layout-principles.md 的完整原则简要说明主视觉、内容优先级、构图选择及理由、共享对齐线、分组间距和图文对应关系；实际文案试排后再确定区域。网格可隐形，主图可跨栏，不默认排成同宽同高的矩形模块；不强迫使用多种形状或曲线。
生成可自由编辑的几何排版网页，而不是只交付静态图片：图内仅含几何形状和简单色块，无装饰、图片或说明文字，图外解释分区。使用统一编辑器提供多种形状与自由编辑，具体能力与操作见 editable-layout.md；保留保存与导入导出。静态示意图仅为附加预览。准确初始布局由确定性坐标建立；用户编辑后以其提供的保存网页或布局JSON更新当前布局版本，并重新试排文案；不能假称看到了用户浏览器里的改动。
默认等待用户确认后进入④；本次任务明确授权连续执行时可自行检查并继续，不跳过该步骤。
### ④ 视觉系统
确定风格前，先问用户对整体视觉有什么要求：氛围与风格、主色与禁用色、参考图片、装饰密度、喜欢或不喜欢的呈现；可合并成一至三问。已有要求先复述，只问缺失偏好。没有偏好时给二至三个简短方向，推荐一个并说明依据；先确认视觉方向再生成母版。仅当前任务明确授权自主选择时记录选择依据。
分析参考的配色、字体层级、图像处理、主题背景、装饰图形与线条，形成可确认的视觉简报。风格服从主题，不固定工业科技风。明确标题、正文与图注的样式层级、强调色语义及复杂背景上的文字承载方式，不能只确定色板而忽略可读性。
### ⑤ 母板与素材计划
先向用户展示本次视觉母版的参考图清单和完整三段式Prompt，等待对该Prompt的明确确认后，再使用可用的 image/image_gen 图像生成能力制作主题视觉母版（若不可用，说明限制并采用明确可用的替代制作工具）。必须好看，有主题背景图、装饰图和装饰线条；处理层次、焦点、渐隐与留白。只借用布局位置与空间预算，不复制几何框、色块或占位底板。默认使用连续统一背景、渐隐过渡、主题边缘装饰与干净留白，图片位置用负空间表达。不得把网络检索到的参考图片当作已生成的母版。
**母版分辨率强制项：** 生成前确定目标实体尺寸和比例，使用当前工具支持的**最高原生生成像素与最高质量选项**，并保持正确长宽比；不得默认为普通预览像素，也不得只在Prompt中声称“4K”。如果无法直接生成所需目标像素，采用高清分层装饰/背景与可编辑矢量版式组合，保存可继续编辑的源文件，标明实际输出像素和局限；不得用插值放大或DPI元数据伪装原生清晰度。
若母版仍出现明显占位框，先删除或重生成背景，再制作模块；不得把框烘焙进最终背景，或用更多矩形补丁遮盖。不要把“无需逐毫米验收框线”理解为允许保留占位框。
用当前③布局约束内容位置与图文面积，背景装饰避让排字；不把装饰位置的微小偏差当作精确布局，不保留占位框。
审查母版美感和主题贴合，确认视觉方向后列出需要制作的素材及实际图区尺寸。不能直接填入全部设备、人物和分镜作为成品。
### ⑥ 模块制作与审查
每个模块先用准确简洁语言说明任务、位置、图区尺寸、必要内容、文字留白和与其他模块分工。
然后输出参考图清单与三段式Prompt，**必须等待用户针对当前Prompt的明确确认**；确认后才调用工具生成或编辑模块图片，不再重复询问同一Prompt的执行授权。修改Prompt后需重新确认。
审查风格、内容、主体一致性与图区适配；需要时增量修改，再继续下一模块。本次跨阶段授权可以合并一般阶段询问，但**不能跳过生成前展示完整Prompt与获得本次确认的独立关卡**（用户针对本次明确豁免预审时除外）；无论怎样都要保留必要的介绍、Prompt文本和结果审查。
### ⑦ 最终排版适配
以③的布局为位置依据、⑤母版为风格依据，精简和重新组织素材，排入文字与精确图表。按 layout-principles.md 检查真实图文的主次、分组、对齐、疏密、重复视角、字体与色彩关系；不能只检查有没有方框。保留解释必要的矩形照片和图表，不为无框裁掉关键内容或把矩形换成等权异形堆叠。实质布局变更按当前项目确认方式处理。
按确认的尺寸交付自包含编辑网页；一个文件可含多个展板页，并共用视觉系统和编号。默认交付可下载的编辑网页，分别保留图文与几何元素，支持自由编辑、撤销重做、保存重开、布局导入导出、SVG与打印；具体按 editable-layout.md 执行。网页无编辑器外部依赖，不把展板压成一张不可编辑的图。PDF/SVG按用户要求额外输出。
保护已规划文字区；不默认用整页重新生图拼版，以免改变素材与留白。需要预览生图或局部合成时，亦须先展示并确认本次完整Prompt；预览标明是视觉预览，不是精确排版。
实际尺寸检查图片区适配及文字容纳，不能靠移动文案掩盖内容侵占。逐区检查多余方框：连续背景优先，用留白、对齐、字号层级、局部细线建立分区；确需底色仅做少量有意义的重点，并作为可编辑元素保留。
### ⑧ 输出与验收
检查视觉美感、主题、信息层级、数据、AI错误、物理尺寸、图像有效分辨率、文字可读性、字体及导出要求。按 layout-principles.md 分别进行缩略图、阅读顺序、最终尺寸、图文对应与文件输出检查；未验证观看效果不声称用户测试通过，未做实际尺寸检查不能以缩略图代替。
验证编辑网页的改字、拖动、尺寸调整、图片替换、撤销重做、保存重开、布局导入导出及打印样式。检查是否有明显占位框、重复矩形底板或已烘焙无法去除的卡片边界。
分别记录视觉通过、文字通过、素材适配通过、网页编辑通过和输出通过；未测试不声称通过。

## 交互与状态
默认每阶段交付成果后等待确认；只做局部任务时不强制完整八步。若本次任务明确授权连续执行，可按授权范围推进，但不会因此跳过每张待执行图像的Prompt展示与明确确认；已同意的同一Prompt不反复请求授权。
审查输出正确部分、最大问题、是否重做、具体修改，必要时给修改Prompt。
维护项目状态和版本，区分待制作、待审查、已确认、暂时接受、待适配、已完成。
用户要求只更新草稿不部署时，遵守该范围；请求更新已安装Skill时按本次已确认的阶段推进并展示变更，不跳过应有的阶段确认；完成授权范围内的保存更新，不以反复询问拖延已获授权的动作。除非用户要求，不打包、不发布网页。
